# Flood Event Agent baseline

用于研究演示的新加坡洪水警报原型。它保存原始响应、按来源去重消息、回放本地已观测记录，并展示警报广播中心和文字道路候选。当前成果是可复现的集成基线；尚无真实 LLM 对照评测、道路拓扑核验或道路避洪安全证据。

## 本地离线运行

需要 Python **3.10 或更新版本**。后端仅使用标准库，包括 SQLite、`http.server` 和 `urllib`；无需安装 Python 第三方包。前端使用随仓库提供的 **Leaflet 1.9.4**，不需要 Node 构建流程。以下命令均从本仓库根目录运行。

```powershell
python -B -m unittest discover -s tests -v
python -B run.py
```

打开 <http://127.0.0.1:8765/>。首次启动加载固定日期 `2026-09-24` 的人工合成示范。默认不轮询网络；不点击采集、真实路线或在线底图按钮时，可以离线回放消息、使用规则提取、查看坐标图和合成路线。按 `Ctrl+C` 停止服务。

要离线导入仓库保留的真实公开回归样本，可使用：

```powershell
python -B run.py --import-archive data/research/pub-2025-05-22.json
```

该样本不是完整历史数据集。默认运行状态保存在 `data/flood.sqlite3`，被 `.gitignore` 排除。可以通过 `--db <本地路径>` 指定另一份数据库、通过 `--port <端口>` 改变端口。测试使用内存或临时数据库和模拟网络响应；这些是回归检查，不是外部服务或科学性能评测。

**报告入口不可用：** 本公开副本排除了 `reports/` 和历史生成报告。现有启动提示与页面仍保留 `/report` 入口；它会跳转到不存在的 `/reports/index.html` 并返回 404。请以本 README 为公开副本说明，不把该链接当作可运行报告。

## 代码结构与数据流

| 文件 / 目录 | 职责 |
| --- | --- |
| `run.py` | 读取本地配置、初始化 SQLite、加载示范、启动仅监听 `127.0.0.1` 的服务 |
| `flood_agent/clients.py` | PUB 请求与分页、失败响应保存、OneMap 路线请求及坐标转换 |
| `flood_agent/normalize.py` | 消息和地点规范化、稳定键、取消引用和状态计算 |
| `flood_agent/store.py` | 原始快照、按来源去重、回放、GeoJSON 和已观测日分布 |
| `flood_agent/extract.py` | 规则提取及未配置的可选 LLM 适配器；候选必须可回查原文 |
| `flood_agent/demo.py`、`spatial.py` | 明确标为合成的路线情景和基础几何操作 |
| `flood_agent/server.py` | 本地 API 与静态页面 |
| `web/` | Leaflet 坐标图、消息、时间回放、日分布和路线情景界面 |
| `tests/`、`fixtures/` | 既有离线回归测试与人工样本 |

原始响应先保存到 `snapshots`，规范化消息按 `(source, message_key)` 去重，地点按内容稳定键去重。`demo`、`live`、`archive` 分别保存和查询；一个来源的取消不会取消另一个来源的消息。无法解析的响应和无效位置仍保留可检查的记录。

`observed_active` 表示在本地观测窗口内未见匹配取消；它不保证道路当前可通行。取消必须匹配 `sender`、`identifier`、`sent` 三元引用。缺少标识、非严格 `Alert` 类型、无可靠发布时间或在本地观测开始前发布的消息可以是 `unknown`；过期与取消另行标注。历史回放采用记录中的发布时间，不能把后来的抓取时刻伪装为同期完整观测。

GeoJSON 坐标顺序为 `[经度, 纬度]`。有效地点输出 `Point`，`location_role` 为 `alert_broadcast_center`；`broadcast_radius_km` 是广播半径属性，**不是淹水面**。无效坐标不产生地图点，但计入 `unlocated_reading_count`。

## 统计与能力边界

`message_count` 是去重消息数，`reading_count` 是非 Cancel 消息中的地点条目数。现有 `alert_message_count` 按“不是 Cancel”计数，因此**包括 unknown 类型消息**，不是严格 `msgType=Alert` 数，更不是真实洪水事件数。`cancel_message_count` 单独计数。未来严格 Alert、unknown 类型和取消统计需要分开设计。

现有 `histogram` 按新加坡发布日显示本地已观测消息和地点分布。当前没有完整历史回填、覆盖状态日历或覆盖感知直方图：缺失日期、失败采集和已成功查询但为零的日期不能据此区分。空结果不能证明某日或全岛没有洪水，也不能证明两年数据完整。

规则与 LLM 的输出都是待核对文字候选，不是道路段几何、封路结论或淹水范围。经 `via` 拼接的 OneMap 路线是候选情景；合成路线的距离和时间只是示范参数。路线差异不证明避洪成功、真实交通因果效应或道路安全。

## 配置与后续网络工作

`.env.example` 只含空凭据位置。需要网络服务时，在本地复制为 `.env` 并自行配置，禁止提交真实凭据。PUB 可使用 `DATA_GOV_API_KEY`；OneMap 实际路线需要 `ONEMAP_TOKEN`。启用在线底图或采集会访问外部服务，网络可用性与配额不属于离线运行保证。

**保持 LLM 未配置。** 现有适配器通过 `LLM_MODEL` 选择模型，既不强制用户要求的 `gpt-6-luna`，也不强制 reasoning 至多 `xhigh`，且其 Chat Completions 参数兼容性尚未验证。不要填写 `LLM_API_KEY` / `LLM_MODEL` 或使用 LLM 按钮；兼容性修改和实际调用应留待另一个正式批准的研究轮次。

源码支持 `--poll` 每 120 秒轮询，但它会持续发起网络请求，不能作为离线示范的一部分。此公开交付不执行轮询、批量回填、道路拓扑、GeoLibre 安装或 A/B/C 实验。
