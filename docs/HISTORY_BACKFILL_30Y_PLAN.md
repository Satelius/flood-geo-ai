# PUB 历史回填扩至 30 年：实施计划

更新日期：2026-10-09（Asia/Singapore）

## 目标

将 PUB Flood Alerts 的逐日查询回填窗口从已完成的两年试点扩展到最近 30 年：

- 结束日：2026-10-07（新加坡时间的昨天，不查询未结束当天）
- 30 年起始日：1996-10-08
- 首尾包含：10,957 天
- 若经证据确认接口不支持候选窗口，保持结束日不变，每次将起始日向后移动一年，再核实并计算最终日数。

工作台保留完整目标窗口。接口明确不可用、请求失败、查询未完成或解析失败的日期仍显示未知，不填为零。

## API 证据与含义

官方 PUB 数据集/API 文档提供 `date=YYYY-MM-DD` 单日查询、可選日期时间截止值和 `paginationToken` 分页；没有多日范围参数，也没有公布历史保留年限或最早可查日期。数据集页面记载创建于 2025-09-03，官方响应示例包含 2025-05-22 数据。参见：

- https://data.gov.sg/datasets/d_f1404e08587ce555b9ea3f565e2eb9a3/view
- https://guide.data.gov.sg/developer-guide/real-time-apis
- https://guide.data.gov.sg/developer-guide/api-overview/api-rate-limits

当前接口按日期调用，因此“30 年是否超出查询区间”不由单个范围参数决定，而由 10,957 个单日任务逐个决定。已完成的两年批次最早非零日为 2025-05-22。成功但返回空 `records` 的日期不能用来推断 PUB 历史档案完整，也不能推断现实中没有洪水；它只代表该次完整响应没有归一化警报消息。批次与报告必须保留这项来源限制。

### 逐年回退规则

1. 先验证 1996-10-08 的日期格式可被接口接受，并记录 HTTP 状态、业务 code、响应结构和分页终止情况。
2. 单日空 `records` 不构成“年份不支持”的证据，也不因此缩短窗口；明确的接口日期/范围拒绝、持续不可用或结构性错误才算能力失败。
3. 由于接口没有范围参数，若单日查询都被接受，就按每日任务执行完整 30 年窗口；单日 404 按 `unavailable` 记录为未知，而不是把整段或该年改成零。
4. 若边界探查证实目标的整年日期都因接口能力限制而无法查询，则将起始日向后移整一年并重验。记录每次尝试、响应证据、最终窗口和未知日期；不根据一次空结果推断整年不可用。

## 实施步骤

1. 更新访谈计划、项目进展、运行文档和中文报告生成器，统一 30 年目标、日期、接口限制和旧两年样本的历史定位。
2. 将日期覆盖 API 和回填批次上限统一扩展到 12,000 天，并保持日期校验及未知值规则。
3. 将热力图默认窗口设为 1996-10-08 至 2026-10-07；保留自定义日期输入、警报消息数/地点条目数切换和完整状态日历。客户端也限制在 12,000 天内，避免超大自定义区间生成巨量页面元素。
4. 让覆盖结果按日期索引，避免 30 年日历逐日重复扫描响应；测试覆盖 30 年批次创建、超限拒绝和日期连续性，不改写已存的两年探测原始证据。
5. 启动带批次 ID 的 10,957 日回填。任务顺序执行、分页共享两秒请求间隔；允许暂停/续跑。根据实测页数，至少需约 6 小时，带额外分页和重试会更久。
6. 验证批次终态和每日期覆盖状态，更新中文实现报告与语料画像。无法完成的日期保持未知。

## 验收标准

- 30 年默认窗口生成 10,957 个连续 SGT 日期，首尾为上述目标日期。
- `/api/coverage` 能返回整个窗口；旧的短区间调用继续兼容。
- 单日成功、分页完整且没有规范警报才标 `complete_zero`；非零日、取消、未知类型、失败、未完成和不可用仍按既有口径分别处理。
- 30 年回填可在中断后续跑；原始响应及分页证据保留；计数不因重复执行膨胀。
- UI 与报告显示总天数、完整/未知状态和来源限制；不把 API 空响应称为真实无洪水。

## 执行结果（2026-10-09）

- 已完成两年批次：2024-10-08 至 2026-10-07，730 天，6 个非零日、724 个完整零日。
- 已确认最早非零日：2025-05-22；官方文档没有承诺更早的历史保留。
- 边界预检：直接请求 `date=1996-10-08` 返回 HTTP 200、业务 `code=0`、`records=[]`，说明单日格式可接受；空 records 不是历史保留证明。
- 执行前检查发现回填批次创建仍有旧 800 天上限，已改为与覆盖查询一致的 12,000 天，并新增 30 年批次创建及超限回归测试。热力图增加按日期 Map 查找和客户端区间上限；全套 73 项测试、JavaScript 语法检查、Python 编译检查通过。
- 批次 `5bef63d4c09d465287bc14a43aa1cfcb` 已完成：10,957/10,957 个日期完整，6 个 `complete_nonzero`、10,951 个 `complete_zero`；无失败、未完成、不可用或未尝试日期。共 21,180 页、262,869 条 API 原始 records。逐日查询审计指标为 8 条非 Cancel 消息（7 条明确 Alert、1 条类型不明），含 8 个地点条目；这些是消息和地点口径，不是经核实洪水次数。
- 有原始 records 的请求日期为 367 天，其中 10,590 天返回空 `records`；另外 361 天有原始 records，但没有规范化非 Cancel 警报消息。`complete_zero` 与空 `records` 是不同口径。本地 archive/live 语料画像的 `record.datetime` 只覆盖 2025-05-22 至 2026-10-07。因此，所有 10,957 天查询完成不等于 PUB 提供了 30 年历史档案；对较早日期只能说本次 API 没有返回可确认的警报消息，不能称为现实中的无洪水日。
- 语料画像已按 30 年目标窗口重跑：21,356 个 archive/live 快照产生 267,186 次 record sighting，按记录内容去重为 262,869 条；其中 262,853 条 `readings` 为空，只有 16 个地点 reading 对象。道路文字规则初筛允许重叠，结果不能当作道路段匹配或准确率。
- 批次查询审计与本地消息表计数略有差异：前者 8 条非 Cancel 消息；本地归日表为 9 条（7 Alert、2 类型不明）。多出的 1 条来自批次外的旧 archive 快照，和 2025-05-22 的未知类型消息文本/地点相同，但消息键不同；报告分别显示两种口径，不把差额当成新增洪水事件。
- 中文报告与摘要已在本地重生成，包含批次结果、6 个非零日期、语料覆盖边界和口径差异；报告及实验输出不随代码发布。报告卡片只读查询批次 API；页面/API 不可用时实时状态为未知。
